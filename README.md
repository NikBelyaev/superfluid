# Superfluid

Локальная Python IDE для одновременной работы в нескольких Git worktree. Electron, React, Vite, Monaco, Pyright и терминальный движок Ghostty, адаптированный из T3 Code.

Текущая версия — **0.1 alpha для macOS**. Основные рабочие сценарии реализованы; это ещё не завершённый production-релиз.

## Запуск

Нужны Node.js 24+ (разработка проверена на 26), pnpm 12.14.0, Git и установленный Python. Для поиска нужен `rg`, для форматирования — `ruff`, для GitHub — авторизованный `gh`, для GitLab — авторизованный `glab` с поддержкой `--description-file`. Эти инструменты приложение не устанавливает и не запускает авторизацию самостоятельно.

```sh
pnpm install
pnpm dev
```

`install` устанавливает зависимости, включая Pyright, скачивает Electron и подготавливает native PTY helper. Pyright включается в приложение; отдельно устанавливать его не нужно. При установке с `--ignore-scripts` отдельно выполните `pnpm setup`. При изменении серверного кода перезапустите `pnpm dev`; React обновляется через HMR.

Запуск собранной версии:

```sh
pnpm build
pnpm start
```

Локальное приложение для текущей архитектуры Mac:

```sh
pnpm dist
```

Результат на Apple Silicon: `release/mac-arm64/Superfluid.app`. Сборка использует локальную ad-hoc подпись; Developer ID, notarization и автоматические обновления пока не настроены.

Можно передать проект при запуске: `pnpm start --project=/absolute/path/to/project`.

## Что работает

- Экран проектов: открыть папку, клонировать репозиторий, поиск, закрепление проектов.
- Обнаружение существующих worktree, создание новой ветки с отдельным worktree, переключение без checkout в текущей папке.
- Собственные вкладки, буферы, курсоры, дерево, история навигации и правые поверхности каждой worktree-сессии.
- Виртуализированное дерево, создание и переименование файлов/папок, удаление в macOS Trash. Изменения несохранённых файлов защищены от переименования и удаления.
- Monaco с Python, подсветкой, completion, hover, диагностикой Pyright и переходом к определению внутри проекта. Lineage сохраняет исходное место и позволяет вернуться.
- Pyright читает `pyrightconfig.json` / `[tool.pyright]` в `pyproject.toml`. Auto-import completion пока отключён: Monaco ещё не применяет дополнительные правки импорта.
- Выбор интерпретатора на worktree. `.venv/bin/python` определяется при первом открытии; окружение не создаётся автоматически.
- Ruff форматирует буфер, сохраняя возможность undo. Переименование символа имеет предварительный просмотр и применяет изменения к буферам.
- Именованные PTY-терминалы и actions: shell, Python-файл, Django runserver. Процесс работает при скрытой поверхности и переключении worktree. Закрытие вкладки терминала не останавливает процесс; Stop делает это явно.
- Плавающий остров: scripts, ветка, Commit → Push → PR, отдельные Git-действия, Changes, процессы и Lineage.
- Изменения рабочего дерева, staged и сравнение ветки с базой; unified/split diff, в том числе новые и удалённые файлы. Разбор patch выполняется в Web Worker.
- Правые вкладки: файл, терминал, diff, изолированный браузер и GitHub PR/GitLab MR. Доступны список по репозиторию или ветке, описание, активность, diff, комментарии и редактирование.
- Init Git для папки без репозитория. Локальный commit работает без remote; push и публикация PR/MR используют remote, выбранный по настройкам Git. При неоднозначном выборе приложение предлагает выбрать remote.

Для проекта с вложенными Git-репозиториями откройте ветку в острове и выберите нужные репозитории. Можно перейти на общую существующую ветку или создать новую от выбранной базы сразу в нескольких репозиториях. Создание worktree переносит выбранную группу в отдельную рабочую сессию; исходные файлы, несохранённые буферы и процессы остаются в прежней. Выбор репозиториев сохраняется отдельно для каждой сессии. Commit, push и PR работают с выбранной группой; частичные ошибки показываются по репозиториям и допускают повтор только неудавшихся действий.

Чтобы временно отложить правки выбранных репозиториев, используйте Stash в меню Git-действий. Сохраняются также новые файлы. Apply stash восстанавливает рабочие файлы и staged-состояние в чистый репозиторий; копия остаётся в stash, в том числе при конфликте.

GitHub и GitLab используют существующую авторизацию CLI (`gh auth login --hostname <server>` / `glab auth login --hostname <server>`). Приложение не хранит токены в SQLite. Сервер и проект определяются из Git remote; корпоративные серверы распознаются по подключениям CLI. **Settings → Source Control** показывает доступные инструменты и аккаунты. Для fork целевой проект при создании PR/MR автоматически выбирается из родительского репозитория; его можно переключить на исходный проект. API host, proxy и сертификаты задаются в CLI.

Откройте **Pull / merge requests** через launcher или палитру команд. Выберите текущую ветку либо весь репозиторий и нужное состояние. **Create PR/MR** использует опубликованную ветку, а **Commit, push & PR/MR** публикует изменения перед созданием. **Edit PR/MR** меняет название, описание, целевую ветку и draft-состояние; изменения кода отправляются обычным push. При ошибке записи сначала обновите МР на сервере, прежде чем повторять действие.

## Клавиатура

| Действие                        | macOS           |
| ------------------------------- | --------------- |
| Найти файл                      | ⌘ P             |
| Команды                         | ⌘ ⇧ P           |
| Поиск по проекту                | ⌘ ⇧ F           |
| Сохранить файл                  | ⌘ S             |
| Следующий / предыдущий worktree | ⌃ Tab / ⌃ ⇧ Tab |
| Перейти к определению           | F12             |
| Назад / вперёд в Lineage        | ⌃ − / ⌃ ⇧ −     |
| Переименовать Python-символ     | F2              |
| Форматировать Python            | ⌥ ⇧ F           |

Actions могут иметь собственные сочетания клавиш. Файл можно открыть справа кнопкой в строке вкладок или перетащить вкладку в уже открытую правую поверхность. Размеры панелей меняются перетаскиванием разделителей и стрелками при фокусе на разделителе.

## Сохранность и процессы

Текст не проходит через React state на каждое нажатие. Recovery пишет версионированные полные снимки в SQLite WAL в отдельном workspace-процессе: idle 350 мс, максимальное ожидание старейшей правки 2 секунды, предупреждение при отставании больше 3 секунд. Старый ACK и старое сохранение не могут удалить более новый черновик.

При обычном закрытии приложение ждёт подтверждения recovery и layout. Если подтверждения нет, окно остаётся открытым. Последние правки после аварийного завершения могут находиться за пределами последнего подтверждённого checkpoint. Это не гарантия нулевой потери данных при отключении питания или отказе диска.

Сохранение проверяет hash дисковой версии, пишет временный файл, делает fsync и rename. Обнаруженные внешние изменения не перезаписываются. Буфер можно отдельно экспортировать через кнопку со стрелкой вниз в редакторе. Автоматическое объединение внешних изменений пока отсутствует.

Git journal сохраняет фазы и результат операции. Push передаёт конкретный commit OID и целевой ref; неожиданный tree, parent или branch останавливает цепочку. Неопределённый результат блокирует новую операцию до явного просмотра журнала/remote через `Inspect result…`; приложение не делает reset или force push.

При полном выходе процессы останавливаются. После перезапуска они не возобновляются автоматически. При скрытии вкладки Ghostty продолжает разбирать вывод в backend worker; повторное открытие получает экран, без повторной подачи ANSI-истории в PTY.

Данные расположены в Electron userData; создаваемые worktree — в его подкаталоге `worktrees`. Удаление userData без предварительного сохранения/переноса worktree удалит находящиеся там файлы. Для отдельного профиля разработки можно задать `SF_DATA_DIR` абсолютным путём. SQLite и черновики содержат исходный текст локально и не шифруются приложением.

## Ограничения alpha

- Проверена macOS Apple Silicon. Windows/Linux не проверены.
- Нет debugger, тестового explorer, пакетного менеджера, LSP-плагинов и SSH/containers.
- Переходы в исходники за пределами worktree, включая stdlib/site-packages, пока не открываются.
- Если после изменения зависимостей в `.venv` или внешнем `site-packages` Python-поддержка показывает устаревший результат, заново выберите интерпретатор worktree, чтобы перезапустить её.
- Нет встроенного удаления worktree и автоматического разрешения Git-конфликтов. Worktree можно удалить обычным `git worktree remove` после сохранения правок и остановки процессов, затем переоткрыть проект.
- PR/MR review ограничен общими комментариями, активностью и общим diff. GitLab показывает события обсуждений, GitHub — commits/reviews в пределах данных `gh pr view`. Inline review, выбор отдельных commits и merge из IDE не реализованы. Работа со старыми GitLab/glab и инсталляциями под URL-префиксом требует отдельной проверки.
- Браузер имеет одну активную native-поверхность; нет devtools и независимых живых вкладок браузера.
- Ограничения: файл 2 МиБ, до 80 моделей/128 МиБ текста, три тёплые worktree, два Pyright-сервера, три watcher, 12 запущенных терминалов, 16 терминальных буферов, 5 000 строк scrollback. Поиск возвращает до 500 результатов. Большие ответы CLI ограничены 4 МиБ.
- Полные нагрузочные release-gates, длительные memory-soak прогоны и проверки восстановления при отключении питания ещё не пройдены.

## Проверки

```sh
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
pnpm test:electron
pnpm test:electron:repositories
pnpm audit --audit-level high
pnpm audit --prod --audit-level moderate
```

`test` собирает backend и проверяет реальные временные Git-репозитории, файловые границы, сохранение, recovery, Pyright и PTY. GitHub-публикация использует тестовый CLI, без обращения к живому GitHub и без создания PR в пользовательских репозиториях.

`test:electron` запускает настоящий Electron в отдельном временном профиле: редактирование, два worktree, терминал, diff, навигация, переключения и восстановление после закрытия. Дополнительно проверяются клавиатурное Git-меню, вкладки файлов и PR, сворачивание острова и его геометрия при 1280×800. PR Summary/Timeline/Code используют локальный тестовый `gh`, без сетевой публикации. Снимки интерфейса и smoke-метрики сохраняются в `test-results/`. Для проверки упакованного приложения задайте `SF_EXECUTABLE` путём к `Superfluid.app/Contents/MacOS/Superfluid`.

CI для macOS подготовлен в `.github/workflows/ci.yml`; его удалённый запуск требует GitHub-репозитория.

## Устройство

- `apps/desktop/src`: окно, sandbox/preload, проверка IPC, нативные диалоги и браузер.
- `apps/server/src`: workspace utility process, SQLite, файлы, Git/GitHub, Pyright и PTY worker.
- `apps/web/src`: интерфейс, Monaco, worktree state, recovery scheduler, Canvas терминала, diff worker.
- `packages/contracts/src`: схемы входящих запросов и типы событий.
- `packages/ghostty`: адаптированные части T3 Code и Ghostty WASM.
