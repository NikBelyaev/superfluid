# Superfluid

Локальная Python IDE для одновременной работы в нескольких Git worktree. Electron, React, Vite, Monaco, ty/Pyright и терминальный движок Ghostty, адаптированный из T3 Code.

Текущая версия — **0.1 alpha для macOS**. Основные рабочие сценарии реализованы; это ещё не завершённый production-релиз.

## Запуск

Нужны Node.js 24+ (разработка проверена на 26), pnpm 12.14.0, Git и установленный Python. Для форматирования нужен `ruff`, для GitHub — авторизованный `gh`, для GitLab — авторизованный `glab` с поддержкой `--description-file`. Эти инструменты приложение не устанавливает и не запускает авторизацию самостоятельно. Поиск работает встроенными инструментами.

```sh
pnpm install
pnpm dev
```

`install` устанавливает зависимости, скачивает Electron и закреплённую версию ty с проверкой SHA-256, подготавливает native PTY helper и собирает поиск Zoekt. Для сборки поиска автоматически скачивается закреплённый Go toolchain с проверкой SHA-256. ty, Pyright и Zoekt включаются в приложение; отдельно устанавливать их в Python-окружение не нужно. При установке с `--ignore-scripts` отдельно выполните `pnpm setup`. При изменении серверного кода перезапустите `pnpm dev`; React обновляется через HMR.

Запуск собранной версии:

```sh
pnpm build
pnpm start
```

Локальное приложение для текущей архитектуры Mac:

```sh
pnpm dist
```

Результат на Apple Silicon: `release/mac-arm64/Superfluid.app`. Эта локальная сборка использует ad-hoc подпись. Релизы macOS для Apple Silicon и Intel собираются через GitHub Actions с постоянным самоподписанным сертификатом.

Можно передать проект при запуске: `pnpm start --project=/absolute/path/to/project`.

## Обновление приложения

Установите подписанный DMG из [GitHub Releases](https://github.com/NikBelyaev/superfluid/releases). В **Settings → About** доступны версия, проверка обновлений и канал **Stable / Nightly**. Nightly содержит более свежие изменения и может быть менее стабильным. Проверка выполняется автоматически, загрузка и установка запускаются вручную; доступное обновление также появляется в боковой панели. Проверку можно вызвать из меню Superfluid или палитры команд.

Подпись проверяет, что обновления выпущены тем же ключом, но не подтверждена Apple и не имеет notarization. При первом запуске скачанного приложения macOS может потребовать разрешение через **System Settings → Privacy & Security → Open Anyway**. Установленную ранее ad-hoc сборку нужно один раз заменить релизной вручную.

Установка сохраняет черновики всех worktree и перезапускает приложение; работающие процессы останавливаются и не возобновляются автоматически. При наличии процессов можно отложить перезапуск. Переключение канала сохраняет проекты и настройки; откат на более старую версию возможен только при совместимом формате данных. Для локальных сборок `pnpm dev` / `pnpm dist` автообновление недоступно.

## Что работает

- Экран проектов: открыть папку, клонировать репозиторий, поиск, закрепление проектов.
- Обнаружение существующих worktree, создание новой ветки с отдельным worktree, переключение без checkout в текущей папке.
- Собственные вкладки, буферы, курсоры, дерево, история навигации и правые поверхности каждой worktree-сессии.
- Виртуализированное дерево: перетаскивайте файлы и папки для перемещения внутри worktree, в том числе группой. Для переименования нажмите F2 и введите новое имя прямо в дереве; расширение файла изначально не выделяется. Создавайте файлы и папки в выбранном каталоге: введите имя прямо в дереве, Enter сохраняет, Escape отменяет; меню действий позволяет переименовать, скопировать в системный буфер обмена или удалить в macOS Trash. Сначала сохраните несохранённые файлы. Цвет имени показывает Git-статус, точка у папки — изменения внутри неё.
- Monaco с Python, подсветкой, completion, hover, диагностикой и переходом к определению. Lineage сохраняет исходное место и позволяет вернуться.
- По версии выбранного интерпретатора автоматически используется ty для Python 3.10+ или Pyright для Python 3.9 и ниже. ty читает `ty.toml` / `[tool.ty]`, Pyright — `pyrightconfig.json` / `[tool.pyright]` в `pyproject.toml`. Если ty не запускается, включается Pyright с причиной в статусе. Auto-import completion пока отключён: Monaco ещё не применяет дополнительные правки импорта.
- Выбор интерпретатора на worktree через **Choose Python interpreter** в палитре команд. Смена перезапускает Python-поддержку с актуальными буферами этой worktree. `.venv/bin/python` определяется при первом открытии; окружение не создаётся автоматически.
- Ruff форматирует буфер, сохраняя возможность undo. Переименование символа имеет предварительный просмотр и применяет изменения к буферам.
- Именованные PTY-терминалы и actions: shell, Python-файл, Django runserver. Процесс работает при скрытой поверхности и переключении worktree. Закрытие вкладки терминала не останавливает процесс; Stop делает это явно.
- Плавающий остров: scripts, ветка, Commit → Push → PR, отдельные Git-действия, Changes, процессы и Lineage.
- Изменения рабочего дерева, staged и сравнение ветки с базой; unified/split diff, в том числе новые и удалённые файлы. Разбор patch выполняется в Web Worker.
- Правые вкладки: файл, терминал, diff, изолированный браузер и GitHub PR/GitLab MR. Доступны список по репозиторию или ветке, описание, активность, diff, комментарии и редактирование.
- Init Git для папки без репозитория. Локальный commit работает без remote; push и публикация PR/MR используют remote, выбранный по настройкам Git. При неоднозначном выборе приложение предлагает выбрать remote.

Для проекта с вложенными Git-репозиториями откройте ветку в острове и выберите нужные репозитории. Можно перейти на общую существующую ветку или создать новую от выбранной базы сразу в нескольких репозиториях. Создание worktree переносит выбранную группу в отдельную рабочую сессию; исходные файлы, несохранённые буферы и процессы остаются в прежней. Выбор репозиториев сохраняется отдельно для каждой сессии. Commit, push и PR работают с выбранной группой; частичные ошибки показываются по репозиториям и допускают повтор только неудавшихся действий.

Чтобы временно отложить правки выбранных репозиториев, используйте Stash в меню Git-действий. Сохраняются также новые файлы. Apply stash восстанавливает рабочие файлы и staged-состояние в чистый репозиторий; копия остаётся в stash, в том числе при конфликте.

GitHub и GitLab используют существующую авторизацию CLI (`gh auth login --hostname <server>` / `glab auth login --hostname <server>`). Приложение не хранит токены в SQLite. Сервер и проект определяются из Git remote; корпоративные серверы распознаются по подключениям CLI. **Settings → Source Control** показывает доступные инструменты и аккаунты. Для fork целевой проект при создании PR/MR автоматически выбирается из родительского репозитория; его можно переключить на исходный проект. API host, proxy и сертификаты задаются в CLI.

Остров автоматически загружает и показывает открытые PR/MR текущих веток только выбранных репозиториев — той же группы, что используется для commit и push. Чтобы увидеть запросы других веток или состояний, откройте **Pull / merge requests** через launcher или палитру команд и выберите репозиторий. Для Detached HEAD доступен список всего репозитория. **Create PR/MR** использует опубликованную ветку, а **Commit, push & PR/MR** публикует изменения перед созданием. Название, описание и целевая ветка редактируются прямо в карточке; draft-состояние меняется в меню действий. Изменения кода отправляются обычным push. При ошибке записи сначала обновите МР на сервере, прежде чем повторять действие.

Для слияния выберите разрешённый репозиторием способ в меню действий и подтвердите Merge повторным нажатием. Auto-merge ждёт выполнения требований хостинга; его можно отменить в том же меню. Если в MR появились новые коммиты, сначала обновите карточку и проверьте diff.

При наведении на Python-символ с зажатой ⌘/Ctrl доступное определение подсвечивается как ссылка. В подсказке также доступны ссылки на модуль и содержащий класс. ⌘-клик по символу или карточке и F12 продолжают цепочку в текущей вкладке. Названия первого и последнего файлов во вкладке возвращают к этим местам. Раскройте меню цепочки, чтобы вернуться к одному из посещённых символов; иконка при наведении на пункт открывает его отдельной вкладкой. Lineage также сохраняет путь назад. Цепочки восстанавливаются отдельно для каждого worktree. Исходники стандартной библиотеки, зависимостей и type stubs доступны только для чтения; код текущего worktree можно редактировать как обычный файл.

## Клавиатура

Откройте поиск через ⌘⇧F, палитру команд или меню новой поверхности. Он объединяет классы, файлы, документы, остальные Python-символы и текст; без выбранных типов ищет всё. Фильтр репозиториев по умолчанию включает все репозитории текущего worktree независимо от выбора в Git-панели; нужный репозиторий можно найти по имени. Выберите результат для предпросмотра, нажмите Enter или Open file для перехода на найденную строку. Окно можно перемещать за свободную область вокруг поля поиска и растягивать за нижний правый угол; двойной клик по этой области разворачивает окно и возвращает обычный размер. Закрыть поиск можно через Esc или клик вне окна. Документы ищутся по имени и содержимому отдельно от остальных файлов: Markdown (`.md`, `.mdx`), reStructuredText, TXT, AsciiDoc и Org. В списке документов видны совпавшие строки; общий поиск по тексту также включает их содержимое. Точные совпадения имён появляются первыми. При первом открытии ⌘P выбирает файлы и документы, ⌘T — классы и символы. Выбор типов и репозиториев сохраняется отдельно для каждого режима и worktree, включая перезапуск приложения; Clear all сбрасывает сохранённый выбор.

Имена файлов и текст ищет встроенный Zoekt helper, Python-символы — LSP. Поиск включает несохранённые буферы текущего worktree. Первый текстовый запрос ищет по файлам, пока индекс подготавливается в фоне; готовый индекс ускоряет следующие запросы. Свежие правки участвуют в поиске сразу. Для старого Python символы индексирует ty, диагностика остаётся за Pyright. Поиск файлов и текста учитывает `.gitignore` и `.ignore`, пропускает окружения и вложенные worktree. Сгенерированные каталоги можно исключить через `.ignore`. Бинарные файлы и файлы больше редакторского лимита 2 МиБ не индексируются.

| Действие                        | macOS           |
| ------------------------------- | --------------- |
| Найти файл                      | ⌘ P             |
| Команды                         | ⌘ ⇧ P           |
| Поиск по проекту                | ⌘ ⇧ F           |
| Найти Python-символ             | ⌘ T             |
| Сохранить файл                  | ⌘ S             |
| Следующий / предыдущий worktree | ⌃ Tab / ⌃ ⇧ Tab |
| Перейти к определению           | F12             |
| Назад / вперёд в Lineage        | ⌃ − / ⌃ ⇧ −     |
| Переименовать Python-символ     | F2              |
| Форматировать Python            | ⌥ ⇧ F           |

Actions могут иметь собственные сочетания клавиш. Вкладку или целую цепочку можно перетащить в уже открытую правую поверхность. Размеры панелей меняются перетаскиванием разделителей и стрелками при фокусе на разделителе.

## Сохранность и процессы

Правки автоматически сохраняются в файлы через 500 мс после паузы ввода, в том числе в неактивном worktree, а также при уходе из редактора или в другое приложение. Запуск actions и терминалов, Git-действия, переключение worktree или проекта, закрытие файла и выход дожидаются сохранения. Перед actions и Git сохраняются также закрытые черновики соответствующего worktree или выбранных репозиториев. При конфликте с внешними изменениями операция останавливается: откройте файл, сравните правки или загрузите версию с диска. ⌘S сохраняет сразу. Для смены ветки закоммитьте сохранённые правки или уберите их в stash.

Текст не проходит через React state на каждое нажатие. Recovery пишет версионированные полные снимки в SQLite WAL в отдельном workspace-процессе: idle 350 мс, максимальное ожидание старейшей правки 2 секунды, предупреждение при отставании больше 3 секунд. Старый ACK и старое сохранение не могут удалить более новый черновик.

При обычном закрытии приложение дожидается записи правок всех загруженных worktree в файлы и сохранения layout. Если запись не удалась, окно остаётся открытым. Последние правки после аварийного завершения могут находиться за пределами последнего подтверждённого recovery checkpoint. Это не гарантия нулевой потери данных при отключении питания или отказе диска.

Сохранение проверяет hash дисковой версии, пишет временный файл, делает fsync и rename. Обнаруженные внешние изменения не перезаписываются. Буфер можно отдельно экспортировать через кнопку со стрелкой вниз в редакторе. Автоматическое объединение внешних изменений пока отсутствует.

Git journal сохраняет фазы и результат операции. Push передаёт конкретный commit OID и целевой ref; неожиданный tree, parent или branch останавливает цепочку. Неопределённый результат блокирует новую операцию до явного просмотра журнала/remote через `Inspect result…`; приложение не делает reset или force push.

При полном выходе процессы останавливаются. После перезапуска они не возобновляются автоматически. При скрытии вкладки Ghostty продолжает разбирать вывод в backend worker; повторное открытие получает экран, без повторной подачи ANSI-истории в PTY.

Данные расположены в Electron userData; создаваемые worktree — в его подкаталоге `worktrees`. Удаление userData без предварительного сохранения/переноса worktree удалит находящиеся там файлы. Для отдельного профиля разработки можно задать `SF_DATA_DIR` абсолютным путём. SQLite и черновики содержат исходный текст локально и не шифруются приложением.

## Ограничения alpha

- Проверена macOS Apple Silicon. Windows/Linux не проверены.
- Нет debugger, тестового explorer, пакетного менеджера, LSP-плагинов и SSH/containers.
- Если после изменения зависимостей в `.venv` или внешнем `site-packages` Python-поддержка показывает устаревший результат, заново выберите интерпретатор worktree, чтобы перезапустить её.
- Нет встроенного удаления worktree и автоматического разрешения Git-конфликтов. Worktree можно удалить обычным `git worktree remove` после сохранения правок и остановки процессов, затем переоткрыть проект.
- PR/MR review поддерживает общие комментарии, активность, общий diff и diff отдельных коммитов. Inline review не реализован. Работа со старыми GitLab/glab и инсталляциями под URL-префиксом требует отдельной проверки.
- Браузер имеет одну активную native-поверхность; нет devtools и независимых живых вкладок браузера.
- Ограничения: файл 2 МиБ, до 80 моделей/128 МиБ текста, три тёплые worktree, два Python LSP-сервера и до двух дополнительных ty для поиска символов со старым Python, до двух процессов поиска Zoekt, 12 запущенных терминалов, 16 терминальных буферов, 5 000 строк scrollback. Поиск возвращает до 500 результатов. Большие ответы CLI ограничены 4 МиБ.
- Полные нагрузочные release-gates, длительные memory-soak прогоны и проверки восстановления при отключении питания ещё не пройдены.

## Проверки

```sh
pnpm lint
pnpm format:check
pnpm typecheck
pnpm test
pnpm build
pnpm test:electron
pnpm test:electron:search
pnpm test:electron:repositories
pnpm audit --audit-level high
pnpm audit --prod --audit-level moderate
```

`test` собирает backend и проверяет реальные временные Git-репозитории, файловые границы, сохранение, recovery, ty/Pyright, Zoekt и PTY. GitHub-публикация использует тестовый CLI, без обращения к живому GitHub и без создания PR в пользовательских репозиториях.

`test:electron` запускает настоящий Electron в отдельном временном профиле: редактирование, два worktree, терминал, diff, навигация, переключения и восстановление после закрытия. Дополнительно проверяются клавиатурное Git-меню, вкладки файлов и PR, сворачивание острова и его геометрия при 1280×800. PR Summary/Timeline/Code используют локальный тестовый `gh`, без сетевой публикации. Снимки интерфейса и smoke-метрики сохраняются в `test-results/`. Для проверки упакованного приложения задайте `SF_EXECUTABLE` путём к `Superfluid.app/Contents/MacOS/Superfluid`.

Electron-тесты по умолчанию запускаются без видимого окна, но требуют графической сессии. Для отладки с окном запустите `pnpm test:electron-verbose`.

CI для macOS подготовлен в `.github/workflows/ci.yml`; его удалённый запуск требует GitHub-репозитория.

`test:electron:search` отдельно проверяет оба режима поиска, изменения на диске, несохранённые буферы, изоляцию worktree и восстановление после перезапуска. Он также входит в `test:electron`.

## Устройство

- `apps/desktop/src`: окно, sandbox/preload, проверка IPC, нативные диалоги и браузер.
- `apps/server/src`: workspace utility process, SQLite, файлы, Git/GitHub, Python LSP и PTY worker.
- `apps/web/src`: интерфейс, Monaco, worktree state, recovery scheduler, Canvas терминала, diff worker.
- `packages/contracts/src`: схемы входящих запросов и типы событий.
- `packages/ghostty`: адаптированные части T3 Code и Ghostty WASM.
